# Задание: покрыть редизайн чек-листа тестами

## Цель

После внедрения редизайна создать минимально достаточное автоматическое покрытие, которое защищает согласованное поведение чек-листа. Тесты должны ловить регрессии в данных и сценариях, а не закреплять текущую DOM-разметку или набор CSS-классов.

Основной источник требований — `ROADMAP_РЕДИЗАЙН.md`. Особенно важно покрыть правила для фильтров, фокуса, обоих сбросов, темы, раздела «Прочее», удаления пользовательского фона и mobile-навигации.

## Границы задачи

### Входит

- Unit-тесты чистых вычислений списка релевантных задач и счётчиков.
- Интеграционные тесты основных пользовательских сценариев React-компонента.
- E2E-проверки критических потоков на desktop и mobile.
- Детерминированные скриншоты четырёх целевых состояний для визуальной регрессии.
- Команды CI для запуска тестов.

### Не входит

- Тестирование каждого текста чек-листа и каждой внешней ссылки.
- Pixel-perfect тестирование всех CSS-свойств или внутренних классов.
- Сетевые тесты ссылок на Kaiten, Google Docs и другие внешние ресурсы.
- Возврат пользовательского фона или тесты загрузки изображения: функция удаляется.

## Предлагаемый стек

| Уровень | Инструмент | Роль |
| --- | --- | --- |
| Unit + integration | Vitest, React Testing Library, `@testing-library/user-event`, jsdom | Быстро проверяет правила данных и доступные действия пользователя. |
| E2E + visual | Playwright | Проверяет реальный браузер, адаптивную навигацию, фиксированную панель фокуса и контрольные скриншоты. |
| CI | npm scripts | Даёт одну предсказуемую точку запуска локально и в CI. |

Перед началом установить тестовые зависимости как devDependencies и добавить скрипты:

```json
{
  "test": "vitest run",
  "test:watch": "vitest",
  "test:e2e": "playwright test",
  "test:visual": "playwright test --grep @visual"
}
```

Нельзя добавлять UI-библиотеку только ради тестов. Допускается небольшая тестовая утилита для рендера приложения с контролируемыми `localStorage` и `matchMedia`.

## Подготовка к тестированию

1. После редизайна вынести чистые вычисления из JSX в небольшой модуль без React: например, `src/lib/checklist-state.js`.
2. Этот модуль может экспортировать `getRelevantTasks`, `getHiddenByFiltersCount`, `getCategoryProgress` и `getOverallProgress`. Он не должен записывать в `localStorage` и не должен знать о CSS.
3. Оставить `DATA`, `PRESETS` и `PRESET_EXCLUDES` единственным источником содержимого. Тесты используют небольшие fixture-наборы только для граничных случаев; не дублируют целый продовый массив.
4. Ввести устойчивые `data-testid` лишь там, где пользовательский доступный контракт недостаточен: корень приложения, прогресс, счётчик скрытых фильтрами, панель фокуса, popover заметок и mobile-навигация. Для кнопок, переключателей, checkbox и select предпочитать role/name.
5. В каждом тесте очищать `localStorage`, восстанавливать `matchMedia` и не зависеть от порядка выполнения тестов.

## Набор unit-тестов

### 1. Релевантные задачи и фильтры

Покрыть функции, которые строят `relevantTasks`.

1. При всех включённых фильтрах релевантны все задачи текущего пресета.
2. Выключенный фильтр скрывает только задачи с соответствующим `feature`.
3. Выключенный фильтр «Таблицы» исключает весь раздел «Таблицы».
4. Если отключены несколько фильтров, каждая строка учитывается только один раз в `hiddenByFilters`; счётчик не является суммой пересекающихся групп.
5. Не привязанная к фильтру задача остаётся релевантной при любых фильтрах.
6. Категория, все строки которой исключены фильтрами, возвращает прогресс `0/0`.
7. Общий прогресс использует только релевантные задачи: скрытая фильтром выполненная строка не входит ни в числитель, ни в знаменатель.

### 2. Фокус

1. Фокус не меняет `relevantTasks`, общий прогресс и прогресс категории.
2. Фокус помечает выполненные релевантные строки как невидимые для рендера, а невыполненные оставляет видимыми.
3. При семи релевантных выполненных строках категория после фокуса не имеет видимых строк, но её счётчик равен `7/7`.
4. Задачи, уже скрытые фильтрами, не входят в счётчик «скрыто готовых» режима фокуса.

### 3. Форматы и разделы

1. Базовый формат не создаёт пустой раздел «Прочее».
2. «Прочее» появляется только для пресетов `tests`, `cd` и `shorts`.
3. В остальных пресетах «Прочее» не создаётся искусственно.
4. При смене пресета строится корректный набор категорий и его локальные счётчики.

### 4. Сбросы и тема

1. Обычный сброс обнуляет `done` и включает все фильтры.
2. Обычный сброс сохраняет текущий формат, тему, заметки и состояние accordion.
3. Полный RESET устанавливает обычный формат, начальные фильтры, чистые задачи, начальное accordion-состояние, пустые заметки и выключенный фокус.
4. Полный RESET **не** меняет `dark` и не удаляет ключ темы из `localStorage`.
5. Начальная тема без ключа в `localStorage` берётся из `matchMedia("(prefers-color-scheme: dark)")`.

### 5. Удаление фона и миграция

1. При старте ключ `bgImage` удаляется из `localStorage`.
2. Удаление `bgImage` не меняет `preset`, `checklist`, `contentFilters`, `collapsed`, `notes` и `dark`.
3. После миграции компонент не читает и не пытается записать `bgImage`.

## Набор integration-тестов

Проверять через доступные роли и пользовательские события, а не через вызов внутренних React handler-функций.

1. **Отметка пункта.** Клик/Space меняет checkbox, счётчик текущей категории и общий прогресс; после перемонтирования отметка восстанавливается из `localStorage`.
2. **Формат.** Изменение select меняет данные на пресетные, удаляет старые отметки и раскрытие; фильтры, заметки и тема сохраняются согласно текущему контракту.
3. **Фильтр.** Нажатие на активный чип переводит его в зачёркнутое интерактивное состояние, меняет «скрыто фильтрами» и `0/0` у полностью исключённой категории.
4. **Фокус.** Переключатель имеет `role="switch"`/`aria-checked`; он скрывает завершённую строку и не изменяет счётчик `готово/всего`.
5. **Обычный сброс.** После выполнения сохраняются preset, заметки, тема и accordion, но отметки пусты, фильтры включены.
6. **Полный RESET.** Действие доступно из меню трёх точек, выполняется без confirm-диалога, сбрасывает всё кроме темы.
7. **Accordion.** Нажатие на раздел раскрывает его; завершённый/неактивный раздел скрывается в соответствии с целевым auto-collapse. Смена пресета не оставляет ключи отсутствующих категорий.
8. **Заметки.** FAB открывает popover и переводит фокус в textarea; шаблон вставляется только в пустое поле; «Очистить» удаляет текст; кнопка закрытия, Escape, click-outside и повторный FAB закрывают окно и возвращают фокус в FAB.
9. **Тема.** Кнопка в шапке меняет тему и сохраняет её; RESET не отменяет этот выбор.
10. **Иконки.** Кнопки темы, меню и заметок имеют доступные имена, а не только SVG без текста.

## Набор Playwright E2E-тестов

### Desktop, 1440 × 1000

1. Открыть приложение с пустым хранилищем; проверить светлую тему, прогресс 0% и активные фильтры.
2. Отметить задачу, отключить фильтр, включить фокус, открыть заметки, перезагрузить страницу. Проверить сохранение ожидаемых данных и отсутствие фона.
3. Сменить формат на «Тест», убедиться в наличии «Прочее»; сменить на «Инвест» и убедиться, что раздела нет.
4. Открыть меню трёх точек, выполнить RESET; тема остаётся прежней, остальные данные возвращаются к началу.
5. Пройти сценарий только клавиатурой: Tab до select, чипа, switch, меню, заметок и checkbox; все действия срабатывают.

### Mobile, 390 × 844

1. Проверить отсутствие горизонтального скролла страницы. Горизонтальная прокрутка допустима только для контейнера чипов разделов.
2. Нажать чип раздела и проверить, что целевая секция попала в viewport, а адрес страницы/данные не изменились.
3. Прокрутить к последней задаче: фиксированная панель фокуса не перекрывает строку; нижний отступ учитывает safe-area.
4. Открыть заметки: popover остаётся в viewport, а FAB расположен над нижней панелью и не пересекается с ней.
5. Выполнить тот же сценарий в тёмной теме.

## Команды и CI

1. `npm run lint` — статическая проверка.
2. `npm run test` — unit и integration; обязателен для каждого PR.
3. `npm run test:e2e` — критические браузерные потоки; обязателен перед merge редизайна.
4. `npm run test:visual` — скриншоты; запускается в CI для PR с UI-изменениями и при ручном обновлении эталонов.
5. В CI сохранять trace/скриншоты Playwright только при падении; baseline и временные артефакты не смешивать.

## Definition of Done

- Все unit и integration-тесты из этого задания зелёные.
- E2E проходят на desktop и mobile.
- Созданы и вручную одобрены четыре visual baseline.
- В тестах явно подтверждены: удаление фона, динамическое «Прочее», правила `relevantTasks`, `0/0`, фокус с неизменными счётчиками, оба сброса и сохранение темы при RESET.
- `npm run lint`, `npm run test`, `npm run build`, `npm run test:e2e` и `npm run test:visual` документированы в README или CI-конфигурации.
- Новые тесты не требуют доступа к внешним ссылкам, интернету или пользовательским данным.
