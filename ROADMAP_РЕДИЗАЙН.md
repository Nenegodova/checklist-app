# Roadmap внедрения нового дизайна чек-листа

## 1. Цель и рамки

Перенести утверждённое направление «Рабочая станция v2» в существующее React-приложение, сохранив пользовательское поведение. Это **редизайн интерфейса**, а не переработка бизнес-логики.

Источники решений:

- `Чек-лист проверки_ краткая инструкция.pdf` — функциональный контракт автора;
- `Чек-лист выпуска - направления (offline).html` — визуальная цель: светлая и тёмная темы, desktop и mobile, без кастомного фона;
- текущее приложение — фактический контракт хранения данных в браузере.

### Что сохраняем без изменения сценариев

| Возможность | Контракт, который нельзя сломать |
| --- | --- |
| Форматы материалов | Выбор пресета меняет набор релевантных пунктов и сбрасывает отметки/раскрытие разделов. |
| Пункты чек-листа | Отметка пункта меняет прогресс и сохраняется после перезагрузки. |
| Фильтры контента | Выключенный фильтр скрывает связанные пункты; прогресс и счётчики считаются только по релевантному после фильтрации набору. Настройки фильтров сохраняются. |
| Режим фокуса | Выполненные релевантные пункты скрываются, пока режим включён, но не исключаются из прогресса и счётчиков. |
| Заметки | Окно открывается из плавающей кнопки; текст и шаблон сохраняются. |
| Темы | Начальное значение берётся из системной темы, ручной выбор запоминается и не сбрасывается полным RESET. |
| Сбросы | «Снять отметки» сохраняет прежнюю семантику: очищает отметки и возвращает все фильтры во включённое состояние, но сохраняет формат, тему, заметки и раскрытие разделов. Полный RESET сбрасывает всё остальное без диалога. |

### Что намеренно удаляем

Пользовательский фон, выбор файла, предпросмотр, очистка фона и вся завязанная на фон стеклянная стилизация. Сохранённое раньше значение `bgImage` нужно удалить из `localStorage` безопасной миграцией. Поддерживать обратную совместимость с самой картинкой не требуется.

### Целевой интерфейс

- Светлая и тёмная палитры: тёплый нейтральный фон, жёлтый `#FFDD2D` как единственный активный акцент, контрастная тёмная тема.
- Desktop: верхняя шапка, левый сайдбар с прогрессом и динамическими разделами, рабочая область с форматом, фильтрами, фокусом и списком пунктов. «Прочее» показывается только в пресетах, где оно реально существует.
- Mobile: компактная шапка с прогрессом, горизонтально прокручиваемый список разделов, который скроллит к нужной секции, список пунктов и фиксированная нижняя зона управления фокусом; заметки остаются на плавающей кнопке.
- Типографика из макета: IBM Plex Sans для интерфейса и IBM Plex Mono для малых служебных счётчиков/меток. Использовать эти open-source гарнитуры локально в сборке, без зависимости от внешней загрузки шрифтов во время работы приложения.

## 2. Принципы реализации

1. Сначала стабилизировать контракт поведения, затем менять разметку и стили. Не смешивать обе задачи в одном большом изменении.
2. Оставить данные `DATA`, `PRESETS`, `PRESET_EXCLUDES` и обработчики отметок источником истины. Разрешённое функциональное уточнение — вывести единый вычисляемый релевантный набор задач для фильтров, счётчиков и прогресса.
3. Все новые визуальные состояния должны использовать уже существующие переменные: `dark`, `preset`, `contentFilters`, `focusMode`, `tasks`, `collapsed`, `notes`, `notesOpen`.
4. Не добавлять стороннюю UI-библиотеку ради одного редизайна. Она увеличит риск изменения поведения и объём регрессии.
5. Оформить цвета, размеры, отступы, радиусы и тени в CSS-переменные. Это визуальная декомпозиция, а не рефакторинг доменной логики.
6. Делать изменения малыми, с рабочей сборкой и ручной проверкой после каждого этапа.

## 3. Последовательность работ

### Шаг 0. Зафиксировать baseline и критерии приёмки

**Зачем:** получить точку, с которой можно отличать ошибку редизайна от уже существующего поведения.

**Действия:**

1. Создать отдельную ветку для редизайна.
2. Установить зависимости из `package-lock.json`; до этого `npm run lint` не запускается, потому что локальный `eslint` не найден.
3. Запустить приложение и сделать скриншоты текущих состояний: светлая/тёмная тема, один раскрытый раздел, отключённый фильтр, включённый фокус, открытые заметки, каждый из девяти форматов, узкий мобильный экран.
4. Ручно пройти сценарии из раздела «Регрессия» ниже и записать фактический результат. Это станет чек-листом проверки PR.
5. Зафиксировать рядом с PR решения из `СЕРЫЕ_ЗОНЫ_РЕДИЗАЙН.md`: динамические разделы, текущая семантика обычного сброса, RESET без сброса темы, правило прогресса и mobile-навигация.

**Готово, когда:** baseline сохранён, принятые решения отражены в задачах PR, а репозиторий после установки зависимостей собирается.

### Шаг 1. Описать карту «старый элемент → новый элемент»

**Зачем:** не потерять функцию при смене композиции.

| Текущий элемент | Целевое представление | Поведение, которое сохраняем |
| --- | --- | --- |
| Заголовок, счётчик, тема, фон, RESET | Шапка: название, прогресс, переключатель темы, меню вторичных действий | Фон исчезает; ручная тема сохраняется даже после RESET; полный RESET открывается из меню с SVG трёх точек из дизайн-направления. |
| `select` формата | Контрол «Формат» в шапке/рабочей области и отображение выбранного формата в заголовке | Смена формата меняет список и сбрасывает связанные данные. |
| Чипы фильтров | Чипы с состоянием: включённые контрастны, выключенные зачёркнуты | Переключение фильтра скрывает только соответствующие пункты. |
| Кнопка «Фокус ON/OFF» | Явный тумблер с текстом текущего состояния и числом скрытых выполненных пунктов | Выполненные пункты скрываются только в режиме фокуса. |
| «Сброс» | Видимое действие «Снять отметки» | Сохраняем текущую семантику: очищаем отметки и включаем все фильтры, не меняя формат, тему, заметки и раскрытие. |
| Заголовки категорий | Accordion-пункты сайдбара на desktop и прокручиваемые чипы на mobile | Desktop автоматически скрывает неактивные разделы; mobile-чип скроллит к разделу. Набор разделов берётся из текущего пресета. |
| Карточки задач | Строки чек-листа с чекбоксом, ссылками и состоянием «готово» | Событие чекбокса, ссылки, фильтры и фокус сохраняются. |
| Плавающие заметки | Кнопка в правом нижнем углу и popover заметок | Автосохранение, шаблон и очистка сохраняются. |

**Готово, когда:** для каждого интерактивного элемента из текущей страницы есть целевое место и проверяемый контракт.

### Шаг 2. Убрать пользовательский фон отдельным, коротким изменением

**Зачем:** не тащить ветвления `bgImage` во все новые компоненты и исключить устаревшее состояние до создания макета.

**Действия:**

1. Удалить `bgImage` из состояния, обработчик выбора файла, скрытый `<input type="file">`, кнопки «Фон» и очистки фона.
2. Удалить все ветки визуальных стилей, которые меняют фон, border, shadow, backdrop-filter или text-shadow из-за `bgImage`.
3. Перестать записывать `bgImage` в общий эффект сохранения и убрать ключ из логики полного сброса; сам ключ очищается миграцией.
4. В одном эффекте миграции при старте выполнить `localStorage.removeItem("bgImage")`. Миграция должна быть идемпотентной и не трогать остальные ключи.
5. Проверить перезагрузку с заранее заданным `bgImage`: картинка не появляется, а формат, отметки, фильтры, тема и заметки остаются.

**Готово, когда:** в проекте не осталось использования `bgImage`, интерфейс не предлагает загрузку фона, а сохранённый старый ключ не влияет на страницу.

### Шаг 3. Ввести дизайн-токены и базовую оболочку

**Зачем:** убрать хаотичные inline-значения из визуальной работы, не переписывая логику.

**Действия:**

1. Описать в `src/App.css` токены двух тем: canvas, surface, elevated-surface, текст, вторичный текст, разделители, hover, жёлтый акцент, опасное действие, радиусы, тени, размеры и safe-area для mobile.
2. Сделать единый корневой класс темы — например, на элементе приложения. Проверить, что он согласован с текущим классом на `document.documentElement`.
3. Добавить базовый reset: `box-sizing`, фон страницы, типографика, стили интерактивных элементов, заметный `:focus-visible`, уважение `prefers-reduced-motion`.
4. Полностью вынести presentation-стили из inline в семантические классы и небольшие CSS-примитивы (button, chip, switch, surface, task row). Это согласованная дизайн-система; расчёты, ключи хранилища и обработчики событий в этом шаге не меняются.
5. Удалить или актуализировать дублирующиеся правила в `src/App.css` и `src/index.css`, чтобы у одного визуального свойства был один источник.

**Готово, когда:** страница уже использует новую палитру и токены, но её информационная архитектура ещё может быть старой; светлая и тёмная тема читаемы без фонового изображения.

### Шаг 4. Собрать desktop-композицию

**Зачем:** desktop-макет задаёт основные зоны и иерархию контента.

**Действия:**

1. Заменить прежнюю колонку на оболочку: шапка + `aside` навигации + `main` рабочей области. Не фиксировать ширину страницы в пикселях: макет 1180 px — референс, а не обязательный viewport.
2. В шапке разместить название, выбранный формат/его контекст, переключатель темы и кнопку меню. Взять из HTML-направления SVG трёх точек, поместить его в локальный компонент/asset и дать кнопке доступное имя «Меню действий»; внешний icon package не нужен.
3. В сайдбаре показать: общий прогресс (процент, дробь, жёлтая шкала), разделы и счётчики выполнения. Разделы строятся по `currentData`: «Прочее» появляется только для «Теста», «ЧД» и «Шортов». Активный раздел обозначить жёлтой вертикальной меткой, как в направлении.
4. В основной области показать крупный заголовок раздела, счётчик раздела, блок фильтров, тумблер фокуса и список строк чек-листа.
5. Сохранить семантику: сайдбар — `nav`, список задач — список/группа чекбоксов, действия — настоящие `<button>`, не кликабельные `<div>`.
6. Визуально проверить длинные задания, несколько ссылок в задании и раздел без видимых пунктов после фильтра/фокуса.

**Готово, когда:** desktop при ширине около 1180 px повторяет иерархию из направления, без горизонтальной прокрутки и без изменения данных/событий.

### Шаг 5. Перенести управления и их состояния

**Зачем:** наиболее высокий риск редизайна — сохранить красивый вид, но исказить сценарий.

**Действия:**

1. Оформить выбор формата как подписанный control «Формат». Дублировать выбранное значение в desktop-заголовке, как в направлении; на mobile не повторять его третий раз.
2. Включённые фильтры оставить активными по умолчанию, а выключенные показывать зачёркнутыми, но интерактивными. Набор фильтров остаётся одинаковым для всех форматов.
3. Ввести единый вычисляемый набор `relevantTasks`: задача попадает в него, если не исключена выключенным фильтром; выключенный «Таблицы» исключает весь раздел. Счётчик «скрыто фильтрами» — число уникальных задач вне этого набора.
4. Вычислять общий прогресс и счётчики категорий только из `relevantTasks`. Если в категории после фильтрации нет строк, выводить `0/0`. Это исправляет текущую недоработку, где скрытые пункты всё ещё участвуют в знаменателе.
5. Перевести фокус в паттерн switch: он скрывает из DOM только выполненные `relevantTasks`, но не исключает их из числителя/знаменателя. Поэтому пустой после фокуса раздел с семью завершёнными пунктами показывает `7/7`.
6. Вынести действие «Снять отметки» рядом с фильтрами и сохранить текущую семантику: очистить все `done` в текущем пресете и включить все фильтры, сохранив формат, тему, заметки и раскрытие разделов.
7. Добавить компактное меню полного RESET. Не показывать диалог: RESET возвращает обычный формат, отметки, фильтры, раскрытие, заметки и фокус к начальным значениям, но оставляет `dark` и его ключ `localStorage` без изменений.
8. Сохранить существующие `localStorage`-ключи и порядок обновления состояния, кроме удаления `bgImage`.

**Готово, когда:** все контролы из шапки/рабочей области проверены кликом, клавиатурой и после перезагрузки; визуальный статус совпадает с данными.

### Шаг 6. Оформить разделы и строки чек-листа

**Зачем:** именно список — рабочая поверхность пользователя; он должен быть быстрым для сканирования и не терять связь с категориями.

**Действия:**

1. Вынести категорию в визуальный блок: заголовок, счётчик `готово/всего`, активное/неактивное состояние. Учитывать два пустых случая: `0/0` после фильтров и, например, `7/7` после скрытия выполненных фокусом.
2. На desktop сохранить accordion и текущее авто-скрытие неактивных разделов. На mobile чип категории плавно прокручивает к её элементу; состав списка разделов не меняется вручную.
3. Оформить пункт как строку с чекбоксом 24 × 24 px на desktop и немного компактнее на mobile, но с интерактивной областью не меньше 44 × 44 px.
4. Выполненный пункт показывать жёлтой отметкой и приглушённым зачёркнутым текстом. Не полагаться только на цвет.
5. Ссылки внутри пункта оформить вторичной компактной меткой и проверить, что клик по ссылке не переключает чекбокс родительского `<label>`.
6. Состояние hover, focus, disabled/hidden и переходы не должны менять высоту строки скачками.

**Готово, когда:** длинные формулировки, ссылки, отмеченные пункты, фильтры и фокус читаемы, а отметка одного пункта корректно обновляет все видимые счётчики.

### Шаг 7. Переработать заметки без изменения данных

**Зачем:** заметки остаются важной функцией, но в направлении имеют собственное, спокойное визуальное место.

**Действия:**

1. Сохранить плавающую кнопку в правом нижнем углу; привести её к жёлтому/контрастному акценту направления.
2. Открывать popover над кнопкой с заголовком, «Вставить шаблон», «Очистить», явной кнопкой закрытия и текстовой областью. Статус «сохранено» пока не добавлять.
3. Использовать текущую строку `notes` и `NOTES_TEMPLATE`; не менять формат сохранённых заметок.
4. Ограничить ширину окна по viewport, чтобы оно не уходило за края на mobile и не перекрывало критичные controls.
5. После открытия перевести фокус в textarea; закрывать через кнопку, повторное нажатие FAB, Escape и клик вне popover. После закрытия вернуть фокус FAB.

**Готово, когда:** заметки редактируются и сохраняются после перезагрузки на desktop и mobile; окно не перекрывается со шапкой и не выходит за экран.

### Шаг 8. Адаптировать mobile и tablet

**Зачем:** в направлении отдельно задан экран шириной 390 px; desktop-сайдбар нельзя просто сжать.

**Действия:**

1. Задать mobile-first/desktop-breakpoint стратегию, сохранив ориентиры 390 px, промежуточный tablet и 1180 px для QA.
2. На mobile убрать постоянный сайдбар: показать общий прогресс в шапке и горизонтально прокручиваемые чипы разделов с текущим счётчиком. Нажатие чипа плавно прокручивает к соответствующему accordion-разделу.
3. Сохранить фильтры доступными, но не позволить им создать горизонтальную прокрутку. Выключенные фильтры должны оставаться различимыми.
4. Сделать панель фокуса фиксированной у нижней границы с `env(safe-area-inset-bottom)` и компенсирующим `padding-bottom` у списка. На mobile поднять FAB заметок над панелью, чтобы элементы не перекрывались.
5. Проверить масштабирование текста браузером, safe-area на iOS и кликабельность всех SVG-иконок.

**Готово, когда:** на 390 px нет горизонтального скролла, все первичные действия достижимы одной рукой, а функциональность равна desktop.

### Шаг 9. Доступность и визуальная полировка

**Зачем:** готовый дизайн задаёт вид, но не заменяет требования к контрасту и управлению с клавиатуры.

**Действия:**

1. Проверить контраст текста, вторичных подписей, выключенных фильтров и зачёркнутых выполненных пунктов в обеих темах.
2. Добавить единый `:focus-visible` для кнопок, select, checkbox, ссылок и textarea.
3. Проверить: Tab/Shift+Tab, Space для checkbox/switch, Enter для кнопок, Escape для меню/заметок, понятные `aria-label` и `aria-pressed`/`role="switch"` там, где они уместны.
4. Не кодировать смысл только иконками: тема, меню, заметки и сброс получают доступные подписи/tooltip. SVG темы и меню взять из файла дизайн-направления, а не из внешней библиотеки.
5. Свести анимации к коротким transition и отключать/упрощать их при `prefers-reduced-motion`.

**Готово, когда:** основные действия доступны без мыши и не возникает неоднозначности между визуальным и реальным состоянием control.

### Шаг 10. Провести регрессию и передать результат

**Автоматические проверки:**

1. `npm run lint`.
2. `npm run build`.
3. Если появятся тесты, добавить не снапшоты внешнего вида, а небольшие поведенческие проверки: выбор формата, `relevantTasks` и `0/0`, фокус с неизменным счётчиком, оба сброса, сохранение темы при RESET, миграция фона, localStorage.

**Ручная функциональная регрессия:**

1. Отметить, снять отметку и перезагрузить страницу.
2. Последовательно сменить все форматы, включая ЧД, Шорты и UGC; убедиться, что прежние отметки не переходят в другой пресет.
3. Выключить каждый фильтр и проверить, что скрываются только релевантные пункты, счётчик скрытого считает уникальные строки, а раздел без релевантных пунктов показывает `0/0`.
4. Включить фокус при выполненных и невыполненных пунктах; убедиться, что выполненные строки скрылись, но счётчики не изменились, затем выключить его.
5. Выполнить «Снять отметки»: убедиться, что очистились отметки и включились фильтры, но формат, тема, заметки и accordion сохранились. Выполнить RESET: всё перечисленное, кроме темы, возвращается к началу без диалога.
6. Написать заметку, вставить шаблон, очистить её и перезагрузить.
7. Изменить тему вручную, перезагрузить, выполнить RESET и убедиться, что ручная тема сохраняется; отдельно проверить начальное значение без сохранённой настройки.
8. Открыть приложение с legacy-ключом `bgImage` и убедиться, что фон не появляется, а остальные данные не удаляются.

**Визуальная регрессия:**

1. Сделать контрольные скриншоты desktop light, desktop dark с фокусом и заметками, mobile light, mobile dark.
2. Сверить их с HTML-направлением: сетка, иерархия, жёлтый акцент, контраст, фильтры, фокус, заметки, отсутствие фона.
3. Проверить длинные тексты, максимальное число ссылок, пустое состояние раздела и все состояния меню.

**Готово, когда:** все сценарии пройдены, нет визуальных дефектов, пользовательский фон отсутствует, а в PR приложены скриншоты четырёх целевых состояний и список принятых решений по серым зонам.

## 4. Рекомендуемое разбиение на PR

1. **PR 1 — контракт и удаление фона.** Миграция `bgImage`, удаление выбора фона, baseline-проверки. Небольшой и легко проверяемый PR.
2. **PR 2 — токены, темы и desktop-оболочка.** Новые цвета/типографика, шапка, сайдбар, рабочая область без изменения логики данных.
3. **PR 3 — controls и список.** Фильтры, фокус, сбросы, строки задач, меню полного сброса, заметки.
4. **PR 4 — responsive, доступность и регрессия.** Mobile/tablet, keyboard-навигация, визуальная полировка, финальные скриншоты.

Такой порядок позволяет откатить визуальный слой без риска потерять пользовательские данные и локализовать регрессии по функциональным зонам.
