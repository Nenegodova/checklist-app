# План доработки интерактивности

Дата аудита: 2026-08-04

## Объём проверки

Проверены desktop 1180×800 и mobile 390×844: стартовый экран, отметка пункта, фильтры, режим фокуса, заметки, переход по разделам, смена формата и полный сброс. Цветовая схема не меняется: сохраняются текущие светлая/тёмная темы, жёлтый акцент, поверхности, линии и типографика.

## Вывод

Базовая механика уже надёжна: отметка сразу обновляет прогресс, фильтры корректно меняют релевантный набор и знаменатель, фокус скрывает выполненное без потери прогресса, заметки получают фокус и закрываются по Escape, мобильная верстка не имеет горизонтального переполнения. Основные риски — действия без подтверждения, потеря контекста после смены формата и слабая обратная связь о сохранении.

## План

### P0 — защитить данные и контекст пользователя

1. **Смена формата.** Если есть выполненные пункты, показывать компактное подтверждение: текущие отметки будут сброшены. После подтверждения прокручивать к началу нового чек-листа, сбрасывать активный раздел и переводить фокус на заголовок первого раздела. Более сильный вариант — хранить отметки отдельно для каждого формата и восстанавливать их при возврате.
2. **Полный RESET.** Заменить мгновенное действие на подтверждение с явным перечислением: формат, отметки, фильтры и заметки. Тема остаётся. На мобильном не оставлять это действие одной абстрактной иконкой.
3. **Снять отметки.** После массового сброса показывать уведомление «Отметки сняты» с действием «Вернуть» на 5–8 секунд. Это частое действие, поэтому подтверждение перед ним будет лишним, а undo даст страховку.
4. **Автопереход после завершения раздела.** Не схлопывать завершённый раздел неожиданно. Сначала показать состояние «Раздел завершён» и кнопку «Перейти к следующему»; если автопереход сохраняется, объявлять его через live-region и возвращать предсказуемый фокус.

### P1 — сделать состояние системы очевидным

1. Заменить постоянное «Сохраняется автоматически» на состояния `Сохраняю…` → `Сохранено` с короткой задержкой и `aria-live="polite"`. Для ошибки localStorage предусмотреть `Не удалось сохранить` и инструкцию не закрывать вкладку.
2. Добавить общий слой коротких уведомлений для сброса, восстановления, вставки шаблона и смены формата. Использовать текущие surface/line-токены; жёлтый — для успешного состояния, danger — только для необратимого.
3. Анимировать только причинно связанные изменения: отметку, прогресс, раскрытие раздела и появление уведомления (120–180 мс). Высота строки не должна прыгать; `prefers-reduced-motion` уже поддержан и должен сохраниться.
4. Для фильтра показывать не только «Скрыто: N», но и результат действия рядом с изменённым чипом или в live-region: например, «Таблицы исключены, скрыто 6 пунктов».

### P1 — удерживать навигационный контекст

1. На mobile закрепить навигацию разделов под sticky-шапкой либо заменить её компактной строкой «Текущий раздел · Выпуск» с раскрывающимся списком. Сейчас после перехода к нижнему разделу чипы исчезают из viewport.
2. После нажатия чипа дождаться завершения прокрутки и только затем фиксировать активный раздел. Не допускать промежуточного несовпадения между активным чипом и фактически видимым заголовком.
3. После смены формата всегда открывать первый релевантный раздел сверху. В текущем поведении новый формат загружается на прежней глубине страницы, поэтому пользователь видит середину нового списка и не получает ясного подтверждения контекста.
4. Добавить действие «Следующий невыполненный» рядом с прогрессом или в режиме фокуса. Оно особенно полезно для длинного списка из 50+ пунктов и использует существующую навигацию по разделам.

### P2 — ускорить работу со списком

1. Сделать текст пункта частью кликабельной зоны чекбокса, сохранив отдельное поведение вложенных ссылок. На mobile это заметно снизит требования к точности касания; минимальная зона 44×44 уже есть у самого чекбокса.
2. Добавить явные `hover`, `active` и `pressed` состояния строкам, иконкам и вторичным кнопкам в рамках текущих токенов. Сейчас focus-visible сильный, а отклик мыши/тача менее выразителен.
3. В режиме фокуса показать короткое пустое состояние для полностью завершённого чек-листа с действиями «Показать всё» и «Снять отметки».
4. Для заметок добавить индикатор сохранения и семантику popover/dialog (`aria-labelledby`, предсказуемый Tab-порядок). Существующие фокус в textarea, Escape, клик снаружи и возврат фокуса на FAB сохранить.

### P2 — доступность и понятность иконок

1. Переключателю темы задать состояние через `aria-pressed` и доступное имя по результату: «Включить светлую тему» / «Включить тёмную тему». На мобильном дать визуальную подсказку через tooltip.
2. Для RESET и заметок добавить tooltip/короткую подпись при фокусе и наведении. Одного `aria-label` достаточно для скринридера, но не для зрячего пользователя, который не знает значение иконки.
3. Объявлять изменение прогресса, скрытого количества и завершение раздела через один ненавязчивый live-region, не заставляя скринридер перечитывать весь список.
4. Проверить контраст приглушённого и зачёркнутого текста в обеих темах, reflow при 200% zoom и полную клавиатурную цепочку после появления подтверждений и уведомлений.

## Порядок реализации

1. **PR 1 — безопасность:** подтверждение смены формата и RESET, undo для «Снять отметки», корректный scroll/focus после смены контекста.
2. **PR 2 — обратная связь:** save-state, live-region, уведомления, завершение раздела без неожиданного схлопывания.
3. **PR 3 — mobile/navigation:** sticky-контекст раздела, стабильное определение активного раздела, «Следующий невыполненный».
4. **PR 4 — polish/a11y:** расширенная зона строки, hover/pressed, tooltips, dialog-семантика заметок, reduced-motion и zoom QA.

## Проверки готовности

- Смена формата с прогрессом не может молча уничтожить отметки и не оставляет пользователя в середине нового списка.
- RESET нельзя запустить случайным нажатием; undo возвращает снятые отметки.
- После любого изменения понятно, сохранено ли оно.
- На mobile текущий раздел и путь к другим разделам доступны на любой глубине страницы.
- Все действия выполняются с клавиатуры, фокус не теряется, изменения объявляются скринридеру.
- Существующие unit/e2e-сценарии остаются зелёными; добавлены тесты на подтверждение/undo, scroll reset, sticky mobile navigation, live-region и восстановление фокуса.

## Ограничения аудита

Скриншоты и ручное взаимодействие подтверждают видимые состояния, но не доказывают полное соответствие WCAG. Не проверялись реальные скринридеры, 200% zoom во всех браузерах, iOS safe-area на физическом устройстве и ошибки/ограничения localStorage.
