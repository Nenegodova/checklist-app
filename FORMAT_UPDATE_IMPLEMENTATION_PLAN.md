## 1. Цель разработки

Заменить плоский нативный список из 28 форматов на иерархический выбор:

- уровень 1 — тип `Обычный` или `UGC`;
- для `Обычный` — сразу список из 8 конечных форматов;
- для `UGC` — полноширинный список из 7 рубрик, затем список конечных подтипов выбранной рубрики;
- на десктопе выбор находится в сайдбаре;
- на мобильном в шапке остаётся компактный контрол с текущим форматом, а полная иерархия открывается в модальном окне.

При этом нужно сохранить существующие правила смены пресета, подтверждения сброса отметок, сохранения состояния, полного reset и прокрутки к началу чек-листа.

## 2. Зафиксированные продуктовые решения

1. Верхние `Обычный / UGC` и UGC-рубрики — навигация внутри выбора, а не отдельные форматы.
2. Чек-лист меняется только после нажатия конечного формата.
3. Если есть выполненные пункты, используется существующее подтверждение смены формата.
4. При отмене подтверждения:
   - действующий формат и чек-лист не меняются;
   - неподтверждённая конечная кнопка не получает выбранное состояние;
   - открытый тип и открытая UGC-рубрика сохраняются.
5. В шапке отображается только реально выбранный формат.
6. Для UGC в шапке показывается жёлтый бейдж `UGC`.
7. Суффикс `(UGC)` удаляется из названий форматов, уведомлений и подтверждения.
8. Внутри UGC-рубрики используются короткие названия; в шапке и служебных сообщениях — самостоятельные контекстные названия.
9. Счётчики типов и рубрик видны и вычисляются из конфигурации.
10. Рубрики оформляются полноширинным навигационным списком, а не чипами.
11. Все новые стили используют существующие CSS-переменные и состояния светлой/тёмной темы.
12. Анимация переключения веток не входит в первую версию и остаётся в бэклоге.

## 3. Что не входит в задачу

- изменение состава пунктов чек-листа;
- изменение логики `getPresetData`;
- новые ключи пресетов или миграция сохранённых ключей;
- хранение отдельных отметок для каждого формата;
- переработка прогресса, фильтров, заметок и навигации по разделам;
- общий редизайн шапки или сайдбара;
- сложные анимации;
- новая тестовая инфраструктура или новые зависимости без отдельной необходимости.

Исключение согласовано отдельно перед этапом C: постоянный тестовый контур
восстановлен в минимальном объёме для контроля дальнейших изменений формата.

## 5. Состояния интерфейса

### Шаг 5. Ввести состояние открытой ветки

В `src/components/ChecklistWorkspace.jsx` добавить отдельное UI-состояние, не смешивая его с `preset`:

```js
const initialLocation = getPresetLocation(preset);
const [formatView, setFormatView] = useState(initialLocation);
const [formatModalOpen, setFormatModalOpen] = useState(false);
```

`formatView` содержит:

- `typeId`: `regular` или `ugc`;
- `categoryId`: идентификатор открытой UGC-рубрики либо `null`.

Это состояние лучше держать в `ChecklistWorkspace`, а не внутри двух экземпляров контрола. Сейчас десктопный и мобильный `FormatControl` одновременно присутствуют в DOM и только скрываются CSS; общее состояние не даст им разойтись после смены breakpoint.

### Правила синхронизации

1. При первом рендере `formatView` вычисляется из сохранённого `preset`.
2. Нажатие типа меняет только `formatView.typeId`.
3. Нажатие рубрики меняет только `formatView.categoryId`.
4. При подтверждённой смене конечного формата `formatView` синхронизируется с новым `preset`.
5. При отмене подтверждения `preset` не меняется, а `formatView` остаётся на просматриваемой ветке.
6. После полного reset состояние синхронизируется с `default` → `regular`.
7. Простое открытие другой ветки не записывается в `localStorage`: сохраняется только реальный конечный `preset`.

Для синхронизации после `switchPreset` и `hardReset` можно использовать эффект на изменение `preset`. Он не должен срабатывать от просмотра типа или рубрики, потому что в этих действиях `preset` не меняется.

## 6. Общий компонент иерархии

### Шаг 6. Перестроить `FormatControl`

`src/components/FormatControl.jsx` должен перестать зависеть от DOM-события нативного `select`. Предлагаемый интерфейс:

```jsx
<FormatControl
  preset={preset}
  view={formatView}
  onViewChange={setFormatView}
  onSelectPreset={requestPresetChange}
  variant="sidebar"
/>
```

Внутри компонент рендерит три смысловых слоя:

1. `Формат` и сегментированный переключатель `Обычный / UGC`.
2. Для UGC — заголовок `Рубрика` и полноширинный список рубрик.
3. Список конечных форматов текущей ветки.

Для обычной ветки второй слой пропускается.

### Полноширинные рубрики

Каждая строка рубрики:

- занимает 100% ширины;
- содержит название слева и количество справа;
- в normal-состоянии не имеет рамки и фона;
- на hover получает `var(--surface-soft)`;
- открытая рубрика получает `var(--surface-soft)`, полужирный текст и жёлтую полоску слева;
- передаёт `aria-pressed` и понятный `aria-label`, например `Рубрика Вопрос—ответ, 6 форматов`;
- управляет панелью подтипов через `aria-controls`.

Визуально этот список должен повторять логику `.section-nav`, но иметь отдельные классы, чтобы последующие изменения навигации по чек-листу не ломали селектор форматов.

### Конечные кнопки

Каждая конечная кнопка:

- занимает 100% ширины;
- показывает короткую подпись;
- выбранный `preset` отмечается жёлтым фоном/рамкой, полужирным текстом и галочкой;
- неподтверждённый кандидат не получает выбранное состояние;
- вызывает `onSelectPreset(presetKey, event.currentTarget)`;
- имеет `aria-pressed={preset === presetKey}`;
- не полагается только на цвет или галочку.

Если пользователь открыл рубрику, которая не содержит текущий `preset`, в видимом списке допустимо отсутствие выбранной строки. Открытая рубрика и реально выбранный формат — разные состояния.

## 7. Интеграция со сменой формата

### Шаг 7. Заменить обработчик `changePreset`

В `ChecklistWorkspace.jsx` изменить обработчик с DOM-события `select` на явные аргументы:

```js
const requestPresetChange = (nextPreset, trigger, source) => {
  if (nextPreset === preset) return;

  actionTriggerRef.current = trigger;
  if (progress.done > 0) {
    setPendingAction({ kind: "preset", value: nextPreset, source });
    return;
  }

  switchPreset(nextPreset);
};
```

`source` нужен, чтобы различать выбор в сайдбаре и в мобильной модалке.

Удалить:

- `headerFormatSelectRef`;
- `sidebarFormatSelectRef`;
- `getVisibleFormatSelect`;
- prop `selectRef` из `FormatControl`.

### Поведение без выполненных пунктов

- формат применяется сразу;
- ветка синхронизируется с новым форматом;
- мобильная модалка закрывается;
- существующий toast остаётся;
- существующие сброс чек-листа, свёрнутых разделов, режима фокуса и прокрутка сохраняются.

### Поведение с выполненными пунктами

- десктоп: открывается `ConfirmationDialog`, сайдбар остаётся на просматриваемой рубрике;
- мобильный: модалка выбора закрывается перед открытием подтверждения, чтобы не было двух `aria-modal` одновременно;
- в `pendingAction.source` запоминается, был ли вызов из мобильной модалки;
- подтверждение применяет формат и не возвращает модалку;
- отмена сохраняет старый формат;
- после отмены на десктопе фокус возвращается на кнопку-кандидат;
- после отмены на мобильном модалка открывается снова на сохранённой рубрике, затем фокус возвращается на кнопку-кандидат или первую конечную кнопку этой рубрики.

Последний пункт нужно реализовать после появления DOM модалки: потребуется `requestAnimationFrame` или эффект, который восстанавливает фокус только после повторного монтирования.

## 11. Доступность и управление с клавиатуры

### Шаг 11. Сохранить качество нативного select

Минимальные требования:

1. Все элементы — настоящие `button`.
2. Тип и рубрика имеют `aria-pressed`.
3. Рубрика связывается с панелью подтипов через `aria-controls`.
4. Конечный формат имеет `aria-pressed` и понятное полное доступное имя, даже если визуальная подпись короткая.
5. Счётчик либо включён в `aria-label`, либо скрыт через `aria-hidden`, чтобы число не озвучивалось без контекста.
6. Галочка имеет `aria-hidden="true"`.
7. Enter и Space активируют все кнопки нативно.
8. `focus-visible` заметен в обеих темах.
9. Модалка и подтверждение правильно запирают и возвращают фокус.
10. После подтверждённой смены сохраняется текущая логика фокуса на первом разделе нового чек-листа.

Поддержка стрелок как у tabs/radio не обязательна для первой версии: структура из обычных кнопок остаётся понятной и полностью управляемой Tab/Shift+Tab. Если позже компонент получит семантику tablist, стрелочное управление нужно добавить одновременно.

## 13. Матрица ручной проверки

### Десктоп

- загрузка с `default`;
- загрузка с сохранённым `ugc18` открывает `UGC → Итоги сообщества`;
- просмотр другой рубрики не меняет заголовок и чек-лист;
- выбор формата при нулевом прогрессе применяется сразу;
- выбор при ненулевом прогрессе открывает подтверждение;
- отмена сохраняет старый формат и открытую новую рубрику;
- подтверждение применяет новый формат и синхронизирует ветку;
- reset возвращает `default` и обычную ветку;
- длинные `Авто / Образование`, `Особый лонг / Тревел` и `Голосовалки за дневник трат` не обрезаются;
- весь сайдбар прокручивается при небольшой высоте окна.

### Мобильный экран

- ширины 320 и 390 px;
- trigger показывает текущий формат и открывает модалку;
- модалка не создаёт горизонтальный скролл;
- длинная рубрика и длинный формат переносятся без наложений;
- закрытие по кнопке, backdrop и Escape не меняет формат;
- выбор без прогресса применяет формат и закрывает модалку;
- отмена подтверждения возвращает в модалку и сохраняет открытую рубрику;
- подтверждение не возвращает модалку;
- фокус не уходит за пределы открытого диалога;
- после закрытия фокус возвращается в шапку.

### Темы и состояния

- normal, hover, focus, open и selected в светлой теме;
- те же состояния в тёмной теме;
- жёлтая полоска, выбранная строка и UGC-бейдж различимы, но не сливаются в один акцент;
- текст и счётчики имеют достаточный визуальный контраст.

### Сохранение и регрессия

- reload восстанавливает выбранный формат;
- старое сохранённое значение `preset` продолжает работать;
- фильтры, заметки и тема не сбрасываются при смене формата;
- отметки сбрасываются только после подтверждённой смены;
- режим фокуса после смены выключается как раньше;
- прокрутка к первому разделу и toast работают как раньше.
